# Audit GitHub Copilot — 2026-07-23

## Portée

Audit en lecture seule du repository central et de la skill utilisateur `product-orchestrator`, située dans `~/.copilot/skills/product-orchestrator/`.

Sources consultées :

- Documentation officielle GitHub Copilot : custom instructions, support des instructions, agent skills, custom agents, hooks, MCP, plugins, cheat sheet.
- Documentation VS Code : prompt files, agent skills, custom agents, agent plugins.
- `github/awesome-copilot`, uniquement comme catalogue d'exemples.
- Fichiers locaux du repository et de la skill installée.

Limites d'accès :

- L'état GitHub distant n'a pas pu être vérifié via `gh` : les commandes `gh repo view`, `gh issue list` et `gh pr list` ont échoué avec `HTTP 401: Bad credentials`.
- Aucun objet GitHub distant, Project, issue ou PR n'a donc été audité au-delà des fichiers locaux.

## Synthèse exécutive

Le repository est cohérent comme repo méta, laboratoire et source de template Copilot-first. Il contient un registre multi-projets (`projects.yaml`), des instructions Copilot natives (`.github/copilot-instructions.md`), des prompts réutilisables (`.github/prompts/`), un template projet (`templates/product-agent-template/`) et une skill user-level installable (`setup/user-skills/product-orchestrator/`).

La skill installée `~/.copilot/skills/product-orchestrator/SKILL.md` est accessible et correspond à la source versionnée `setup/user-skills/product-orchestrator/SKILL.md`.

Le principal risque identifié est la duplication des responsabilités entre instructions, prompts, skills et documentation longue. Cette duplication est parfois utile comme redondance de sécurité, mais devient risquée lorsqu'elle recopie des procédures détaillées.

## Logique actuelle observée

- `.github/copilot-instructions.md` porte les règles non négociables du repo méta.
- `.github/prompts/*.prompt.md` encode les modes exécutables `DISCOVER`, `BOOTSTRAP`, `ADOPT`, `RESUME`, `STATUS`, `REPLAN`, `CLOSE`.
- `docs/copilot/orchestration.md` documente les workflows en détail.
- `setup/user-skills/product-orchestrator/SKILL.md` agit comme routeur cross-repo user-level.
- `templates/product-agent-template/.github/copilot-instructions.md` rend un projet enfant autonome.
- `templates/product-agent-template/.github/prompts/*.prompt.md` porte les modes locaux d'un projet enfant.
- `templates/product-agent-template/.github/skills/project-orchestrator/SKILL.md` route les demandes locales vers les prompts du projet.

## Forces à préserver

- Gouvernance Copilot inline dans `.github/copilot-instructions.md`.
- Modes explicites pour éviter l'implémentation prématurée.
- Séparation entre orchestrateur cross-repo et orchestrateur projet.
- Template projet indépendant de la stack technique.
- Mémoire durable volontairement rare.
- Vérification indépendante documentée et reliée à la PR template.

## Simplifications à faible risque

1. Supprimer la documentation de migration Claude obsolète si elle n'a plus de valeur opérationnelle.
2. Corriger les références de chemins du template vers `docs/learning-lifecycle.md`.
3. Déclarer que les prompts sont la source d'autorité des procédures exécutables, et réduire `docs/copilot/orchestration.md` à objectifs, invariants et pièges.
4. Dans `product-orchestrator`, garder le routage et les garde-fous cross-repo, mais éviter d'y recopier les procédures détaillées des modes.
5. Dans `project-orchestrator`, garder seulement collecte d'état, arbre de routage local et lien vers prompts locaux.
6. Garder la redondance de sécurité sur les règles non négociables dans les instructions méta et template.
7. Garder la PR template comme formulaire de preuve, sans en faire une deuxième définition des critères de fin de tâche.

## Vérification du frontmatter des prompts

Formats observés :

- `.github/prompts/*.prompt.md` : `mode: agent` + `description`.
- `templates/product-agent-template/.github/prompts/*.prompt.md` : `mode: agent` + `description`.

Documentation consultée :

- VS Code "Use prompt files in VS Code" documente les champs frontmatter `description`, `name`, `argument-hint`, `agent`, `model`, `tools`.
- Le champ documenté pour choisir l'agent est `agent`, avec les valeurs `ask`, `agent`, `plan` ou le nom d'un custom agent.
- GitHub Copilot cheat sheet indique que les prompt files sont supportés dans VS Code et Visual Studio, en preview dans JetBrains/Xcode, et non supportés sur GitHub.com ni Copilot CLI.

Conclusion :

- La compatibilité de `mode: agent` n'est pas confirmée par la documentation officielle consultée.
- La modification automatique n'est pas certaine dans cette étape.
- Format cible recommandé pour une étape distincte : remplacer `mode: agent` par `agent: agent`, après validation sur les surfaces réellement ciblées.
